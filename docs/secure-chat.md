# 房间加密聊天：威胁模型与安全边界

本文描述的是实现 `src/net/secureChat.ts`、`src/ui/chatPanel.ts`，以及服务器中 `rtc` 信令转发分支实际能做到的事。它不是“绝对安全”的声明，每一条都对应可以复现的测试。

## 1. 架构

- **文字**：通过 WebRTC `RTCDataChannel` 点对点发送，传输层是 DTLS 加密的 SCTP。
- **语音**：通过 WebRTC 音频轨道点对点发送，使用 DTLS-SRTP 加密。
- **游戏服务器**：只把 SDP/ICE 信令转发给同一房间的另一个座位。它不解析、不记录、不保存这些信令，也接触不到聊天正文和语音。
- **密码学**：全部使用浏览器自带的标准 WebRTC 实现，没有自己编写任何加密算法或协议。
- **连接方式**：同一房间内两两之间各建立一条连接（4 人最多 6 条）。座位号较小的一方发起连接，以免双方同时发起造成冲突。

## 2. 保护对象与攻击者

| 保护对象 | 攻击者 | 结果 |
| --- | --- | --- |
| 文字正文、语音 | 网络窃听者 | 无法读取：内容经 DTLS / SRTP 加密 |
| 文字正文、语音 | 被动的游戏服务器或托管方 | 无法读取：正文不经过服务器（金丝雀测试验证） |
| 文字正文、语音 | 主动篡改信令的服务器（替换 DTLS 指纹做中间人） | 能够冒充，但**两边的安全码会不一致**。只有双方都核对过安全码，才算防住 |
| 本地记录 | 之后使用同一设备的人 | 记录只保存在内存里，离开房间或关闭页面后消失，不写入存储 |

**明确不在保护范围内：**

- **恶意的网页代码**：网页代码由服务器下发。如果服务器下发了恶意代码，它可以直接读取正文，端到端加密对此无效。要防住这一点，需要改成签名的桌面或移动客户端。
- **终端被攻破**：已中毒的设备、浏览器插件、屏幕录制都能看到明文。
- **截图或转述**：接收方本人截图或转告他人，无法阻止。
- **未核对安全码时的中间人**：没核对就聊天，无法确认对方身份。
- **元数据**：见第 5 节。

## 3. 密钥

- **生成**：每个标签页在内存中生成一张临时的 ECDSA P-256 证书（使用 `RTCPeerConnection.generateCertificate`），不能导出，也不落盘。
- **交换**：DTLS 握手由浏览器完成。证书指纹放在 SDP 中，由服务器转发。浏览器会强制要求对方实际使用的证书与 SDP 中的指纹一致。
- **验证**：安全码 = SHA-256(`paintwar-chat-v1` + 双方指纹按字母排序) 的前 64 位，显示为 20 位数字。如果服务器替换了指纹，两边算出的安全码不同。双方需要当面或通过其他渠道比对。
- **轮换**：刷新页面会生成新证书，安全码随之改变。如果已核对的队友安全码发生变化，界面会撤销“已核对”，并显示红色提示“安全码已变化，请重新核对”。之前的信任不会被静默继承。每次 DTLS 连接都使用临时 ECDHE 协商，具有前向保密。
- **防重放**：DTLS / SRTP 自带重放保护。应用层还会按消息 ID 去重，同一条消息只显示一次。

## 4. 传输与中间服务

- **服务器能看到**：哪些座位之间在建立连接、什么时间、信令的大小，以及 SDP 中的 ICE 候选地址（含 IP）。
- **服务器看不到**：聊天正文和语音。
- **大小限制**：游戏消息仍限制在 4 KB；只有 `rtc` 信令允许到 12 KB，且只转发给同一房间内在线的其他座位。
- **观战者**：不参与聊天。
- **不存在的组件**：没有离线消息、消息队列或 TURN 中继。直连失败时，界面会显示“直连失败”，而**不会**改走服务器转发明文。

## 5. 本地数据与元数据

- **本地数据**：聊天记录最多保留 100 条，只在内存中。没有 `localStorage`、IndexedDB、通知、`console` 日志或错误上报。显示时一律使用 `textContent`，防止 XSS。离开房间时会关闭所有连接、停止麦克风，并清空记录和核对状态。
- **元数据泄漏**：
  - 使用了公共 STUN 服务器（Google），它和对方玩家都能看到你的公网 IP。
  - 服务器知道谁和谁、在什么时间建立了连接。
  - 消息长度和发送频率不做填充，可以被网络观察者推测。

## 6. 可复现的验收（`.work/scripts/chat-check.mjs`，两个真实 Chrome 实例）

| 声明 | 结果 |
| --- | --- |
| 两端安全码一致，格式为 20 位数字 | 通过 |
| 金丝雀消息送达对方 | 通过 |
| 金丝雀不出现在任何 WebSocket 帧中（即服务器路径） | 通过 |
| 金丝雀不出现在服务器日志中 | 通过 |
| 金丝雀不出现在 `localStorage` / `sessionStorage` 中 | 通过 |
| 在聊天框打字不会触发准备或移动 | 通过 |
| 使用模拟麦克风时，对方能收到实时音频轨道 | 通过 |
| 离开房间后，对方的连接与音频被关闭，本地记录被清空 | 通过 |
